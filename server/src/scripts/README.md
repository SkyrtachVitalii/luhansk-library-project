# Модуль скриптів міграції та генерації (`server/src/scripts`)

Цей каталог містить **автономні TypeScript-скрипти**, призначені для автоматизації міграції архівного вмісту старого сайту бібліотеки в нову систему (база даних MongoDB + хмарне сховище Cloudinary).

---

## Структура каталогу

```
server/src/scripts/
├── migration/
│   └── index.ts    # Єдиний головний скрипт міграції
└── README.md       # Документація модуля
```

---

## Головний скрипт: `migration/index.ts`

- **Команда запуску**: `npm run migrate` (або `npx ts-node src/scripts/migration/index.ts`)
- **Призначення**: Здійснює повний універсальний цикл міграції даних архіву бібліотеки.

### Основні етапи та функціонал:

1. **Мережева надійність та ідемпотентність**:
   - Примусово налаштовує Google DNS (`8.8.8.8`, `8.8.4.4`) для стабільного з'єднання.
   - **Етап 0: Очищення Cloudinary (`cleanCloudinary`)** — видаляє попередньо завантажені ресурси у хмарній папці `library_archive_main/`.
   - **Очищення MongoDB (`Post.deleteMany({})`)** — повністю очищає колекцію `Post` перед імпортом, що забезпечує ідемпотентність повторних запусків.

2. **Обробка та завантаження файлів (Етап 1)**:
   - Сканує папку `migration/upload`.
   - **Retry Logic (`uploadWithRetry`)**: Виконує до 3 спроб завантаження кожного файлу з затримкою при мережевих збоях.
   - **Визначення типів ресурсів**: Документи та архіви (`.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.zip` тощо) завантажуються як `raw`, медіафайли — як `image` / `auto`.
   - **Великі файли**: Для файлів понад 6 МБ використовується `upload_large` з розбиттям на чанки.
   - **Генерація `file_map.json`**: Автоматично створює підсумкову карту відповідності відносних шляхів файлів до нових URL-адрес у Cloudinary та зберігає її в `migration/file_map.json`.

3. **Міграція бази даних MongoDB (Етап 2)**:
   - Зчитує архівний файл `migration/posts.json`.
   - **Заміна посилань**: Замінює локальні посилання `/upload/...` (включно з кириличними URI) на актуальні Cloudinary URL з карти `file_map.json`.
   - **Прев'ю та контент**: Автоматично витягує URL першого зображення для `imageUrl` та формує валідний HTML-вміст.
   - Зберігає нові записи `Post` у MongoDB із збереженням старого ID (`oldId`) та оригінальних метаданих (`originalData`).
