# Інструкції та контекст проєкту для Агента Antigravity

Цей проєкт є монорепозиторієм сайту бібліотеки. Він складається з трьох основних частин: `server` (бекенд), `client` (фронтенд) та `migration` (скрипти для імпорту архівних даних).

---

## 1. Загальні правила для всього проєкту (Global Constraints)

- **Мова коду:** Весь проєкт використовує **TypeScript**. Завжди суворо типізуй функції, інтерфейси, пропси та стейти. Не використовуй `any`.
- **Запуск:** Звертай увагу, що серверна частина використовує тип модулів CommonJS (`"type": "commonjs"` у package.json), але розробка ведеться через `ts-node` та `nodemon`.
- **Архітектура:** Модулі мають бути ізольованими. Не переплітай логіку сервера, клієнта та міграцій між собою.

---

## 2. Модуль: SERVER (`/server`)

### Технологічний стек & Залежності:
- **Framework:** Express v5.1.0 (Увага: використовується нова 5-та версія Express).
- **База даних:** MongoDB через Mongoose v9.0.0.
- **Real-time:** Socket.io v4.8.1 (Веб-сокети).
- **Файли:** Multer v2.0.2 (для парсингу `multipart/form-data`) + Cloudinary v2.8.0.
- **Тестування:** Jest + Supertest для API-тестів.

### Правила для Агента:
- **Контроль версій Express:** Оскільки використовується Express 5, обробка помилок в асинхронних маршрутах відбувається автоматично. Не пиши зайві блоки `try-catch` там, де Express може самостійно перехопити помилку в middleware.
- **Завантаження файлів:** Усі медіафайли (книги, обкладинки) мають спочатку оброблятися через `multer` (як буфер або тимчасові файли) і одразу завантажуватися в Cloudinary. Не зберігай файли на постійній основі локально на сервері.
- **Веб-сокети:** Логіка `socket.io` має бути винесена в окремий модуль/сервіс (наприклад, `src/socket/`), щоб не засмічувати файл `src/index.ts`.
- **Тести:** Перед релізом фіч обов'язково запускай `npm run test`. Написання тестів для нових ендпоінтів за допомогою `supertest` є обов'язковим.

---

## 3. Модуль: CLIENT (`/client`)

### Технологічний стек & Залежності:
- **Framework:** Next.js v16.2.4 (App Router), React v19.2.5.
- **Стейт-менеджмент:** Redux Toolkit v2.11.0 + React-redux.
- **Стилі:** Sass (SCSS) v1.89.2.
- **Анімації:** GSAP v3.14.2.
- **Інші важливі пакети:** `html-react-parser` (для рендерингу HTML з бази даних бібліотеки), `jose` (для JWT/Auth на стороні Next.js Middleware), `socket.io-client` для конекту з сервером.

### Правила для Агента:
- **React 19 & Next.js 16:** Використовуй Server Components за замовчуванням. Додавай директиву `"use client"` лише туди, де потрібен Redux, GSAP анімації або хуки React (useState, useEffect).
- **Стилізація:** Пиши модульний SCSS (`*.module.scss`). Уникай глобальних стилів.
- **Анімації:** При роботі з GSAP обов'язково використовуй очищення контексту (наприклад, `gsap.context()` або хук `useGSAP`), щоб запобігти витоку пам'яті під час ререндерів React.
- **Безпека:** Для перевірки сесій у Next.js Middleware використовуй виключно бібліотеку `jose`. `bcryptjs` та `mongoose` у package.json клієнта присутні, але їх використання дозволено **лише в Server Actions** або Next.js API Routes, вони не мають потрапляти у клієнтський бандл.

## 4. Модуль: MIGRATION (`/migration`)

### Призначення модулю:
Ця папка містить скрипти для парсингу, скачування та імпорту архівних файлів старого сайту бібліотеки. Вона переносить текстові дані в MongoDB, а медіафайли — в Cloudinary.

### Правила для Агента:
- **Особливість стеку:** Оскільки окремого package.json для міграцій немає, скрипти працюють у контексті серверних залежностей (`mongoose` та `cloudinary` беруться з конфігурації сервера). Запуск має відбуватися через `ts-node`.
- **Логіка імпорту:**
  1. Скрипт викачує архівний файл/лінк старого сайту.
  2. Якщо є файл (зображення, PDF книги): він завантажується в Cloudinary, а скрипт отримує `secure_url` та `public_id`.
  3. Усі текстові метадані (назва книги, автор, опис) разом із посиланням на Cloudinary записуються в MongoDB згідно зі схемами Mongoose, визначеними в `/server/src/models`.
- **Обмеження та безпека:**
  - **Пагінація та ліміти:** Ніколи не запускай імпорт всього архіву одночасно. Скрипт повинен обробляти дані батчами (пакетами, наприклад по 20-50 елементів), щоб не перевантажити ліміти Cloudinary та пам'ять процесу.
  - **Логування:** Обов'язково створюй лог-файли (`migration.log`) або детально виводь у консоль статус: що успішно завантажено, а на якому файлі сталася помилка.
  - **Idempotency (Повторюваність):** Перед імпортом запису перевіряй у базі даних MongoDB, чи ця книга/файл вже не були імпортовані раніше (наприклад, за унікальним старим ID або URL), щоб уникнути дублікатів.

---

## 5. Файли, які Агенту ЗАБОРОНЕНО чіпати самостійно

Без прямої команди користувача у чаті, агент **не має права модифікувати**:
1. Конфігураційні файли: `next.config.js`, `tsconfig.json` в обох папках.
2. Файли конфігурації ESLint та Jest.
3. Готові файли налаштування підключення до бази даних (`db.ts` або аналогічні на сервері).
